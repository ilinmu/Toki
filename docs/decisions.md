# 工程取舍

记录几项影响面较大的决定，以及当时的理由与后续空间。

| 决定 | 理由 | 影响 / 后续 |
| --- | --- | --- |
| 库用单个 JSON + 原子 rename，不用 SQLite | 纯 Go、零依赖（`modernc.org/sqlite` 会带进很大的依赖树）、万级照片全量序列化只需几十毫秒；筛选在内存里做 | 十万级以上应换 SQLite + FTS；`Library` 已把读写收在一个类型里，替换面小 |
| 缩略图放磁盘 JPEG + 内存 LRU | 复用 `ui.DecodeBitmap`（GPU 位图），并用 `ReleasePixels` 控制内存；键里含编辑状态，编辑即失效 | 磁盘约 4 KB/张（288 px） |
| 编辑只做几何变换与基础色彩 | 这些调整足够日常使用，且能用同一套渲染同时服务缩略图、预览与导出 | 更复杂的滤镜与局部调整见 `todo.md` |
| 裁剪用滑块，不做拖拽选框 | 原生 UI 里实现「可拖拽的裁剪框 + 八向把手 + 约束比例 + 实时重排」约需 300–500 行输入处理，且易与网格/滚动手势冲突 | 现在的宽度/高度/位置/拉直滑块能表达同样的结果；拖拽是下一步增强 |
| 拉直限制在 ±15° | 避免极端角度下大面积黑边 | 需要更大角度时用 90° 旋转 |
| 导出水印用内嵌 7×13 点阵字体（`x/image/font/basicfont`） | 不引入字体文件与字体渲染依赖，二进制保持小巧 | **只支持 ASCII**：中文水印不会画出字形 |
| 元数据写 XMP（JPEG 内嵌）+ `.xmp` 边车 | XMP 是跨工具标准（Lightroom/Photos/ExifTool 都读），实现只需百来行；写回时保留原始 EXIF 段 | 非 JPEG 用同名边车，避免破坏原文件 |
| 从不删除原文件，只有「移出库」 | 误删照片不可恢复，而「移出库」完全可逆（重新扫描即回来） | 需要真删时用 Finder；后续可加「移到废纸篓」并走系统 API |
| 库整体刷新用 `Invalidate()` 而非 `Update(nil)` | `Update(nil)` 会在主线程执行 nil 函数并崩溃；`Invalidate` 对未就绪窗口安全 | 所有后台完成回调统一走 `refreshUI()`，并以 `winReady` 闸门保护首帧前调用 |
| 监视用 `mygo.WatchFiles`，每个文件夹一条，事件后只重扫该文件夹 | 递归监视 + 去抖由框架负责；局部重扫避免每次事件全库遍历 | 极深目录树可加 `MaxEntries` 与忽略规则 |
| HEIC/AVIF/RAW 不支持 | 标准库 + `x/image` 无解码器 | 需要时接 `libheif`（cgo）或外部转换；纯 Go 无 cgo 是刻意选择 |
| 网络功能不做 | 照片管理器的核心是本地库；不联网也就没有账号、遥测与隐私面 | 云备份/共享若要做，需要另行设计 |
| 收藏彩纸用 Go 自绘，不引入 JS 库 | 应用里没有 JS 运行时；自绘粒子可以按区域缩放、与主题同源 | 见 `app/confetti.go`；`canvas-confetti` 只是效果参照 |
